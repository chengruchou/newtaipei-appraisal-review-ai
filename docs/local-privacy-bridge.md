# Separate loopback privacy bridge and signed C2 sink

The bridge is a separate FastAPI application in
`adapters/local/privacy_bridge.py`. Never mount it on the cloud application. It
reuses the existing local review, bundle, mapping, export and refill services;
public privacy-v1/document-v1 and shared service/task schemas are unchanged.

## Trusted construction

```python
app = create_privacy_bridge(
    PrivacyBridgeConfig(
        workspace=private_workspace,
        origin="http://127.0.0.1:5173",
        authority="127.0.0.1:8766",
        sources=source_configuration,
    ),
    sessions=server_sessions,
)
```

`source_configuration` maps UUID handles to
`PrivacyBridgeSource(path, snapshot, policy_digest)`. Paths are server-owned
absolute paths inside the private workspace; snapshots are existing
`LocalSourceSnapshot` values from the actual source store. Each request rechecks
file hash, size, ownership, links, confinement and source-store bytes. HTTP never
accepts a path, URL, file upload, output filename, key or mapping.

`server_sessions` maps preprovisioned bearer tokens to independent
`PrivacyBridgeSession` instances. Tokens need at least 32 characters and should
be generated by the local provisioner. Do not put tokens or private keys in logs,
reports, cloud configuration or client requests to the backend. This is an
isolated development-session adapter, not SSO or production identity assurance.

The session constructor receives:

- `principal_id: str`, `source_ids: frozenset[UUID]`;
- `human: BridgeReviewConfirmation`, used by that session's
  `LocalPrivacyReviewService`;
- `review`, `builder: LocalSanitizedBundleBuilder`,
  `verifier: LocalSanitizedVerifier`, `mappings: LocalMappingService` and
  `key_reference: UUID`;
- `sink: PrivacyExportSink | CloudExportSink`, `sources: LocalSnapshotReader`
  and `results: PrivacyBridgeResultResolver`.

The human adapter's principal must match the session. Review/human/builder/
verifier/mapping service instances cannot be shared between sessions. Supply the
same live review authority and verifier to the builder and mapping service.
Keys/store/sources and output directory are local dependencies, not request DTOs.
The workspace must already be private and owned. Unsupported POSIX protections
fail closed; this app does not provide Windows filesystem equivalence.

Bind the server explicitly to loopback with proxy trust and access logging off:

```python
uvicorn.run(app, host="127.0.0.1", port=8766, proxy_headers=False, access_log=False)
```

The middleware independently requires a loopback peer, exact numeric-loopback
Host (including port), exact configured Origin and exact bearer token. It rejects
forwarded headers, duplicate sensitive headers, queries, non-JSON writes and
bodies above 64 KiB. Preflight permits only GET/POST and Authorization/Content-Type
for the configured Origin, with no file/session side effects. Responses use
`no-store`, `nosniff`, no-referrer and a restrictive CSP. Errors use only
`local_privacy_request_rejected`, without exception values or original content.

## Local HTTP operations

All paths below begin with `/local-privacy`. Every actual request includes
`Authorization: Bearer <local session token>` and the browser's configured Origin.
Use authenticated fetch and local blob URLs for PDF/PNG display; plain image tags
or browser navigation do not supply the authorization header.

| Method and path | Input | Result |
| --- | --- | --- |
| GET `/sources` | None | `{sources: [{source_id}]}` from the session allowlist |
| POST `/sources/{source_id}/open` | `{}` | Existing `PrivacyReviewView` from actual local scanning |
| GET `/review` | None | Current `PrivacyReviewView` |
| GET `/pages/{page}` | None | Owned original page as PNG; records page preview |
| POST `/review/pages` | Existing `ReviewPrivacyPage` | Advances page-review revision |
| POST `/review/add` | Existing `AddPrivacyRegion` | Adds a local manual region |
| POST `/review/edit` | Existing `EditPrivacyRegion` | Edits region/category/entity |
| POST `/review/remove` | Existing `RemovePrivacyRegion` | Dismisses with an explicit reason |
| POST `/review/confirm` | Existing `ConfirmPrivacyReview` | Explicit source-review confirmation |
| POST `/exports/preview` | `{reviewer_text?: string or null}` | `preview_id`, public `manifest`, sanitized `reviewer_text`, `payload_digest` |
| GET `/exports/{preview_id}/pdf` | None | Exact provisional sanitized PDF |
| POST `/exports/{preview_id}/confirm` | `{payload_digest}` | Confirms exactly the retrieved preview |
| POST `/exports/{preview_id}/transfer` | `{}` | `{manifest, state: "transferred"}` only after the sink returns |
| POST `/restore/{result_id}` | `{}` | `{local_id, manifest}` for separately authorized local refill |
| GET `/restored/{local_id}` | None | Session-owned restored PDF bytes |

Every view response includes `X-Privacy-Review-Digest`, exposed through CORS. Use
this value in the explicit source-confirm request rather than reimplementing
canonical hashing in JavaScript. Existing version commands include `case_id`,
`snapshot_id` and `revision` equal to `command.selection_revision`. Extra fields
are forbidden. Coordinates use PDF bottom-left in unrotated CropBox space.

The UI must display the source page before its explicit page-reviewed action.
All page review/edit operations advance revision and invalidate prior approval
and export previews. Source confirmation issues one exact local approval only
through an explicit authenticated command; scanning/previewing never approves.

## One exact build and confirmation

The provisional sanitized bundle is built and verified once. Its public manifest,
PDF hash, exact manifest JSON, optional sanitized text and fixed filename are
bound by `payload_digest`. A confirmation is accepted only after that preview's
PDF was retrieved and with the same digest, current review and unexpired approval.
Preview lifetime defaults to five minutes, capped at fifteen.

Transfer uses a cached owned-bundle adapter for the existing export gate. It does
not run a second raster build or regenerate occurrence IDs. The gate persists and
authenticates its encrypted map, invokes the live exact confirmation, then reads
the same map again and checks current approval/verifier/payload before the sink.
Mapping/key/confirmation failures cause zero sink calls.

One preview permits only one transfer attempt. The attempt is consumed even if
storage, signing, admission or catalog publication fails; retry is not automatic.
A sink failure may mean a committed document exists. The owner must reconcile
admission receipts before initiating another export. Local handles are retained
for reconciliation. Cancellation waits for an already-running synchronous worker
before releasing the session lock; it does not terminate an in-flight storage or
network call. Full process-crash/session/key recovery is not implemented here.

## Real signed document admission

`adapters/local/privacy_document_sink.py` supplies the trusted `CloudExportSink`:

```python
sink = CloudExportSink(
    ingestion=documents,
    principal=principal,
    private_key=local_signing_key,
    key_id=local_signing_key_id,
    purposes={
        (criteria_source.case_id, criteria_source.document_id): "criteria",
        (forms_source.case_id, forms_source.document_id): "forms",
    },
    on_admitted=record_committed_metadata,
)
session.sink = sink
```

This key must match a configured `TrustedExportKey` on the **same** real
`Ed25519ExportVerifier` used by `documents`. Actor/case ownership must match the
trusted principal. The parent's explicit document grants must permit each
configured purpose for INGEST and READ. Keys remain local; no request can choose
purpose, principal, signer, public key or source binding.

The bridge binds its existing exact UI confirmation to the sink. The returned
channel reuses `ConfirmedDocumentExport` as both gate confirmation and gate sink.
It parses actual immutable PDF bytes/pages, checks the hash/size/manifest/source,
then signs existing `ExportClaims`/`PrivacyAttestation` and calls the actual
`DocumentTransferService.ingest`. It performs authorized byte-for-byte readback
before calling `on_admitted(DocumentMetadata)`. That callback can register the
canonical reference in the parent's SQLite catalog; it must not record original
paths, mapping values or keys. The browser can subsequently list the backend's
admitted references. No unconditional confirmation or fake successful sink exists.

`sink.receipts` retains committed metadata even when readback/catalog callback
fails. It is an in-process reconciliation aid, not a durable transaction joining
mapping, C2 admission and the parent's catalog. A failure after C2 writes but
before a receipt is returned remains an unknown outcome to reconcile separately.

C2 document-v1 supports only the PDF and signed manifest. For this sink, omit
`reviewer_text` or send null at preview preparation; non-null text is rejected
rather than silently discarded. Local review-response text belongs to its own
separately authorized workflow. The generic gate still supports explicitly
reviewed sanitized text with sinks that implement that contract.

The original snapshot identity and digest remain local. The public privacy
manifest's opaque document ID expresses lineage, while C2 allocates a separate
cloud document ID/version and binds their hash to the sanitized bytes. Raster
sanitization deliberately removes native text; downstream extraction must use
configured raster/OCR/model processing bound to these new admitted references.
Original fixture text/evidence cannot be reused as if extracted from the new PDF.

## Authorized local restoration

The server-owned resolver implements
`resolve(principal_id: str, result_id: UUID) -> PrivacyBridgeRestore`. The returned
local context contains an approved `RehydrationPlan`, current publisher,
rehydration authority, processor, OCR port and confined `download_path`. The
backend lookup receives only authorized opaque result identifiers. The local
plan/mapping/path and key are never sent as backend request data.

The bridge requires a session-owned encrypted map with matching selected source,
verifies the authorized downloaded bytes against the publisher, and invokes the
existing `LocalPrivacyRefillExecutor`. Publisher ownership/currentness and file
identity are checked again after processing. It writes only a fresh generated
private directory and `final-local.pdf`, using exclusive/no-follow atomic output;
existing originals/downloads and aliases cannot be overwritten. Local IDs are
session-scoped. Restored PDFs are never passed to the export sink.

## Synthetic construction and evidence

`tests/unit/privacy_bridge_fixture.py` exports
`build_synthetic_privacy_bridge(workspace, authority, origin, *, sink=None,
results=None, principal_id="synthetic-owner", case_id=None)`. It requires an empty
existing directory and creates an actual CJK PDF, local source store, preview/
raster processing and encrypted mapping store. Returned state exposes `app`,
`config`, `owner`, `source_id`, `source`, `token`, `maps`, `keys`, `tracker` and
`close()`. Its repr hides credentials. Keep tokens/keys in local memory or ignored
private runtime state only. The helper uses explicit synthetic candidate/OCR
adapters and does not approve source review or export automatically. Inject the
parent's real C2 sink/resolver and use matching principal/case grants.

From the integration worktree's declared-dependency editable `.venv`:

```bash
PYTHONPATH="$PWD/src" .venv/bin/python -m pytest \
  tests/unit/test_privacy_bridge.py tests/unit/test_privacy_document_sink.py \
  --basetemp=artifacts/privacy-bridge-checks/tmp/acceptance
```

The combined bridge/sink checkpoint passed 39 tests, using actual uvicorn/httpx
loopback HTTP, PDF parse/render/refill, AES-GCM/native local files, Ed25519 and
C2/SQLite ingestion/readback. Criteria and forms each exercise signed admission.
The wider relevant privacy/document run passed 257 tests with eight platform
skips and seven dependency deprecation warnings. No AWS calls occur. Tests
also reject cross-site/DNS-rebinding headers, malformed/oversized/path bodies,
foreign handles, stale/expired previews, ciphertext/key failures, unsupported
text, replaced downloads and output aliases. Callback/unknown outcomes retain
receipts/maps and do not automatically repeat transfer. Source/download bytes and
cloud-calculated pixels remain unchanged in successful local refill tests.

These results are local HTTP/adapter evidence, not browser human participation,
production SSO, real OCR/model accuracy, a distributed transaction, deployment
acceptance or complete backend-job integration. The parent and frontend owners
compose and validate those additional paths separately.

The paired-source browser rehearsal is composed by
`scripts/privacy_browser_rehearsal.py`; see
[its construction and backend handoff](privacy-browser-rehearsal.md). It uses the
same production application factory and sink. A successful transfer does not
authorize a backend result or local restoration.
