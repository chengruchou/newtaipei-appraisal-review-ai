# Writer compatibility and migration note (formal multi-context output)

Scope of this change set: multiple-context output, versioned template/font/
field-map registry, opaque placeholder fields and local backfill. See
[ADR 0019](adr/0019-formal-multi-context-output-and-placeholders.md).

## Contract compatibility

- `appraisal_review.ports.pdf.PDFWriter` is unchanged and remains the only
  writer protocol.
- `PDFWriteRequest` adds `additional_results` (default empty) and `PDFField`
  adds `placeholder_token` (default None). Existing single-context requests and
  field maps remain valid inputs. Consumers parsing newly serialized fields
  with strict unknown-field rejection must regenerate; defaults do not make old
  readers accept new keys.
- `schemas/service-v1.json` and `schemas/local-service-v1.json` were
  regenerated by `scripts/export_service_contracts.py` for the two new optional
  fields.
- The embedded output metadata `/AppraisalReviewWriterVersion` is now `"2"`.
  Reopen verification requires the matching version, so artifacts written by
  version 1 will not verify against version-2 expectations (and vice versa);
  regenerate goldens with the writer that will verify them.

## Behavior changes and their gates

- A verified case with multiple comparisons now writes one complete PDF only
  when the composed writer declares `supports_multiple_contexts` exactly `True`
  and the approved field map covers every verified comparison; every other
  combination keeps `verified/unsupported_contexts`. Fakes, mocks and the
  existing local-service confined writer remain single-context.
- Multiple-context requests fail closed on: an unbound or duplicate context, a
  second case ID, a field matching no comparison, or a map leaving any
  comparison unwritten (no partial first-context report).
- `PDFRenderConfig.approved_font_sha256` (optional) makes preflight verify the
  font file bytes; registry-composed configurations set it automatically.
- Placeholder fields render their opaque token in cloud writes.
  `LocalPlaceholderBackfill` re-identifies locally from the pristine template,
  accepts only local file destinations, and verifies (never edits) the
  downloaded cloud artifact. `S3PDFWriter` and the AWS confined writer refuse a
  writer that reveals placeholders.

## Open follow-ups (not in this change set)

- The reference local service (`adapters/local/service.py`) and its legacy
  `ArtifactManifest` retain single-context/local-only semantics. Integration adds
  a separate `FencedArtifactManifest` (`artifact-manifest-v2`) with primary and
  complete contexts, review-context scope, fenced publication and exact assets.
  `ServiceResult.artifacts` accepts the legacy/new union; consumers regenerate
  for the new version. The projection owner must validate the actual multi-context
  producer/service/reader path. See [canonical migration](service-contracts.md).
- Formal government templates, official field maps and reviewed CJK production
  fonts remain E's controlled inputs; current CJK coverage is synthetic-font
  test evidence, not formal-template acceptance.
- B1 full-case PDF goldens should regenerate against writer version 2 and add
  multiple-context golden manifests.

## Suggested #5 status update

Multi-context output, template/font/field-map registration and de-identified
placeholder output are implemented behind the unchanged `PDFWriter` protocol
with synthetic-template evidence (deterministic double-write, reopen text and
geometry checks, CJK glyph-coverage failures, fail-closed partial reports).
Keep #5 open for formal template/font/map provisioning, local-service manifest
migration and B1 golden acceptance.
