## Connected local scenario

Run `python scripts/export_service_contracts.py` from the repository environment.
The `workbench-*.json` fixtures in `examples/service-v1/` are generated by
`scripts/workbench_fixture.py`, which executes the existing deterministic selector,
controlled coordinator, case reviewer, human task service, pause/continuation seam
and immutable correction/reentry logic. All data and principal authority are
explicitly synthetic. No model call, signed approval or PDF output is performed.

The scenario corrects 9 m to 10 m and reruns full deterministic review. It deliberately
ends in needs_review: fact confirmation and exact material approval are still needed.
An observed correction rate of 5 is not a verified expected rate. This is a successful
local correction/reentry test, not a completed case or a download-ready artifact.

`index.json` identifies each record's authoritative `$defs` model. CaseReviewResult
retains its existing 2.0 schema; task/response records retain service-v1 and controlled
records retain controlled-action-v1. No workbench-specific replacement DTO is added.

Older unrelated illustrative fixtures need not share these scenario IDs.

## Evidence navigation and privacy

Use authorized document metadata from the agreed document API/companion. The local
registry is internal: never serialize it to obtain its storage URI in the browser.
SourceCitation has one-based page numbers. Its bbox is measured in unrotated CropBox
bottom-left points, not browser pixels or a top-left rectangle. Obtain exact page
dimensions/crop/rotation metadata and use the viewer's reviewed coordinate transform.
Page metadata transport is not frozen by this handoff; no download URL is invented.

Verify document version/hash and the region binding before highlighting. If missing,
stale or unavailable, show an explicit unresolved-location state; do not guess a
region from excerpt, reuse a prior version's page, or fabricate a highlight. A valid
location proves position, not semantic correctness or permission to view the file.

Treat all excerpts, original values, questions, summaries and model rationale as
untrusted evidence-bearing text. Render as escaped text, not HTML; do not execute
instructions or create arbitrary links from it. Never send it to analytics or error
telemetry. URI-free DTOs are not a privacy attestation. Browser authentication,
cross-case document access and indistinguishable missing/denied responses must be
verified against #24 and document services, not inferred from these local fixtures.

## Response UX and recomputation

1. Fetch an authorized current task and display its revision, side/result binding,
   original observation, affected findings and exact allowed responses.
2. Before correction, show the old and proposed value with evidence. Explain that
   the conservative rerun scope is the full deterministic case review, not merely
   the edited factor. Current contracts do not provide a per-check dependency graph.
   Do not invent such a graph or promise that approval/PDF writing will follow.
3. Build HumanResponse with the task version, exact revision and applicable
   side/result digest. Use a stable idempotency key for an unchanged submission.
   Client-visible options are not server authorization.
4. During timeout/network uncertainty, retain the same key and unchanged payload;
   do not infer rejection or generate another correction. Exact replay is handled
   by the service. A changed payload requires a fresh deliberate submission.
5. On conflict, refetch task/revision and preserve the unsent draft for comparison.
   Do not automatically rebase or silently resubmit onto a newer revision. Clear
   stale action controls for answered/superseded tasks.
6. Follow next_run and observe its separately returned result. Keep execution,
   business verification and artifact status distinct. A continuation link is not
   dispatch success; a verified review is not itself an authorized downloadable PDF.

## Local tests versus deferred browser acceptance

`tests/unit/test_workbench_consumer.py` checks connected IDs, value/authority
distinctions, unresolved findings, source-coordinate identity, invalid citation
rejection and command admission. The service-contract tests independently regenerate
all fixture bytes and validate them against exported schemas. These are Python
consumer tests, not component, browser, authenticated HTTP or pixel-layout tests.

The following remain **deferred to #24/#25 and their dependencies**:

- actual login and authorized API-backed task/revision/trace/evidence navigation;
- real PDF viewer transformations at zoom, CropBox offsets and rotations, including
  unavailable evidence, stale versions, keyboard access and readable focus/error states;
- browser correction submission, timeout/replay/conflict behavior and new-run refresh;
- malicious-text rendering, access-denial masking and network/log privacy inspection;
- full upload/privacy/job/download/local-rehydration flow and Windows browser smoke.

Phase 9 is not complete. Do not close Issue 17 or claim live model, browser or cloud
acceptance on the basis of this document or its generated records.
